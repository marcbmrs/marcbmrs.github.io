# Skill: Review Publish Readiness

## Purpose

Check whether a Marcos Dev repository change is safe to publish or hand off.

## Procedure

1. Identify changed files and separate them from unrelated dirty work.
2. Confirm the affected public URL and whether publication was explicitly requested.
3. Check links, images, metadata, responsiveness, accessibility, and obvious console/runtime risks.
4. Confirm no credentials, private files, raw client originals, or unrelated local outputs are being published.
5. Confirm `robots.txt`, `sitemap.xml`, `CNAME`, or README updates when affected.
6. Summarize tests, residual risks, and exact next action.

## Output

Publish readiness checklist with status: safe to publish, hold, or needs user decision.
